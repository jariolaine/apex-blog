# Application development context

Follow `AGENTS.md` for application responsibilities, source ownership, tool use,
and database authorization.

## Recover project context

At the start of each task, read all files in `memory-bank/`, beginning with the
six core files:

1. `memory-bank/projectbrief.md`: stable project scope and goals.
2. `memory-bank/productContext.md`: user workflows and product behavior.
3. `memory-bank/systemPatterns.md`: architecture and implementation relationships.
4. `memory-bank/techContext.md`: application technologies, constraints, and dependencies.
5. `memory-bank/activeContext.md`: current focus, recent work, and next decisions.
6. `memory-bank/progress.md`: completed milestones and remaining work.

The files in `memory-bank/reference/` hold focused detail behind the core
summaries.

## Maintain continuity

After meaningful application changes, update the affected memory files.
Keep `activeContext.md` current and record completed milestones or changed
status in `progress.md`. Update the other core files when the product context,
architecture, or technical constraints change.

When asked to "update memory bank", review all core and reference files and
edit only what needs updating. Preserve useful decisions and their dates;
distinguish completed source changes from observed application behavior.
An unresolved question records a pending decision, not a new task assignment.
